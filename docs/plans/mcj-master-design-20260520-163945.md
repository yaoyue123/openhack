## Problem Statement

openhack 当前的 agent-loop.ts 是一个 111 行的扁平循环：单次 `streamText` 调用 + `stepCountIs` 步数限制。没有循环检测、没有上下文压缩、没有结构化记忆、没有终止条件判断。两届黑客松 20 支队伍的实践证明，这种架构在长链路攻击（Web→提权→横向→域控）中必然失败——模型陷入无限循环、上下文膨胀导致降智、失败路径无法被记住导致重复犯错。

需要重写核心循环，加入 Harness 控制层（代码守住底线）和记忆系统（文件持久化状态），使 agent 在长链路渗透中保持稳定。

## What Makes This Cool

- agent 的思考过程完全可见——`state.md` 是实时更新的 markdown 文件，人类可以直接阅读、编辑、回溯
- 经验自蒸馏（Phase 2）：每次成功攻击后自动提取经验写入 `memory/experience.md`，下次遇到类似挑战直接复用
- "Prompt 是引导，代码是边界"——代码只做循环检测/终止/上下文预算，不干涉 agent 如何思考

## Constraints

- TypeScript, Vercel AI SDK (`ai` package) — 当前代码库纯 async/await，不引入 Effect 重写
- 允许破坏性变更——重写核心循环
- 记忆系统用文件（Markdown/JSON），不用向量数据库
- 经验自蒸馏是 Phase 2，先稳定 Harness + 记忆基础
- 设计偏好：For Future 的 Less Than Nothing 哲学——架构尽可能少，给 LLM 推理空间

## Premises

1. 当前扁平的 agent-loop 无法通过补丁修复，需要重写 — confirmed
2. 控制层应该是 Observer with Minimal Intervention 模式（观察为主，必要时注入提示，不覆盖 agent 决策），不是 Supervisor 模式 — confirmed
3. 记忆应该用文件（Markdown/JSON），不用向量数据库 — confirmed
4. 经验自蒸馏是第二阶段，先稳定 Harness + 记忆基础 — confirmed

## Approaches Considered

### Approach A: 纯自然语言 FSM (For Future 风格)
- Summary: 零硬编码逻辑，纯自然语言驱动 FSM，文件总线共享状态
- Effort: M | Risk: Med
- 语义转换条件依赖模型一致性，弱模型可能不稳定

### Approach B: 代码 Harness + JSON 状态板 (AI小分队v2 精简版)
- Summary: 硬性数值守卫 + 结构化 JSON 状态板，完全可测试
- Effort: L | Risk: Low
- 更重的代码维护负担，对 Less Than Nothing 哲学来说过重

### Approach C: 混合 — 代码边界，自然语言核心 (SELECTED)
- Summary: 代码守住底线（循环检测/终止/上下文预算），自然语言保持 AI 自由度
- Effort: M-L | Risk: Low-Med
- 两全其美——可靠的底线 + 灵活的核心

## Recommended Approach

**Approach C: 代码边界，自然语言核心**

核心原则：代码做三件事（循环检测、终止判断、上下文预算），其余全部交给 agent 自由发挥。状态持久化为 markdown 文件，agent 通过工具调用自由读写。

### 核心模块设计

#### 1. Harness (`src/harness/`)

**LoopGuard（循环检测）**

代码级别的守卫，不依赖模型判断：

```typescript
// harness/loop-guard.ts
interface LoopGuardConfig {
  windowSize: number;     // 比较窗口大小，默认 5
  similarityThreshold: number; // 相似度阈值，默认 0.8
  maxRepeats: number;     // 最大重复次数，默认 3
}

interface LoopGuardResult {
  isLoop: boolean;
  repeatCount: number;
  suggestion?: string;    // 给 agent 的提示
}

// 实现：对最近 N 步的工具调用 + 参数取哈希，
// 比较相似度。超过阈值且重复 > maxRepeats 次则判定为循环。
// 判定循环后注入提示到下一轮消息："你似乎在重复相同的操作，尝试不同的方法。"
```

关键设计决策：循环检测用**工具调用签名**（toolId + 参数哈希）而非原始文本，因为工具调用是 agent 行为的最小单位。两个工具调用参数的 80% 相似度 = 大概率在重复。

**BudgetGuard（上下文预算）**

```typescript
// harness/budget-guard.ts
interface BudgetConfig {
  maxTokens: number;          // 硬上限，默认 100000
  compressThreshold: number;  // 触发压缩的阈值，默认 70000
  preserveRecentSteps: number; // 压缩时保留最近 N 步，默认 5
}

interface BudgetGuardResult {
  shouldCompress: boolean;
  currentUsage: number;
  action: 'continue' | 'compress' | 'terminate';
}
```

当 token 使用量超过 `compressThreshold` 时，触发压缩：
1. 保留最近 N 步完整消息
2. 将更早的消息替换为 `compressor.ts` 生成的摘要
3. 摘要写入 `memory/attack-log.md`
4. 如果压缩后仍超过 `maxTokens`，终止循环

**Terminator（终止判断）**

```typescript
// harness/terminator.ts
interface TerminatorConfig {
  flagPatterns: string[];     // flag 正则模式
  maxStepsWithoutProgress: number; // 无进展最大步数，默认 10
}

interface TerminatorResult {
  shouldTerminate: boolean;
  reason?: 'flag_found' | 'no_progress' | 'budget_exhausted' | 'agent_declared_done';
}
```

终止条件（代码判断，不依赖模型主观）：
1. 检测到 flag → 终止（成功）
2. 连续 N 步无新发现（LoopGuard 判定 + 无新 findings 写入）→ 终止（失败）
3. 上下文预算耗尽 → 终止（预算不足）
4. agent 通过 state.md 声明 `status: done` → 终止（agent 自主结束）

#### 2. Memory System (`src/memory/`)

**state.md（agent 当前状态）**

这是 agent 的"大脑"——一个 markdown 文件，agent 在每轮迭代后通过 `state-write` 工具更新。格式由 system prompt 约定（自然语言约束），不由代码强制（代码只读写文件）：

```markdown
# Current State

## Objective
[当前攻击目标]

## Phase
recon | exploit | lateral | escalate | done

## What I Know
- [关键发现 1]
- [关键发现 2]

## What I've Tried
- [已尝试的方法和结果]

## Next Step
[下一步计划]

## Blockers
- [遇到的阻碍，如果没有留空]
```

agent 自由写入这个文件。Harness 只读取 `Phase: done` 作为终止条件之一。

**Phase 解析策略：** 使用简单正则，大小写不敏感，容错设计：
```typescript
// harness/terminator.ts 中的解析逻辑
function parsePhaseFromState(stateContent: string): string | null {
  // 匹配 "## Phase" 标题下的内容，忽略大小写和多余空白
  const match = stateContent.match(/^##\s*Phase\s*\n\s*(\w+)/mi);
  return match ? match[1].toLowerCase() : null;
}
// 终止条件：parsePhaseFromState(content) === "done"
```

**memory/ 目录**

```
memory/
├── attack-log.md     # 每步简要记录：时间戳 + 动作 + 结果
├── findings.md       # 关键发现清单（端口、漏洞、凭证等）
├── failed-paths.md   # 失败路径记录（防重复）
└── experience.md     # Phase 2：成功攻击后的经验提炼
```

每个文件的内容由 agent 通过工具调用维护。system prompt 约定格式，代码不强制。

**Compressor（上下文压缩）**

```typescript
// memory/compressor.ts
interface CompressionResult {
  summary: string;           # 压缩后的摘要
  preservedMessages: ModelMessage[]; # 保留的最近消息
  tokensSaved: number;
}

// 策略：
// 1. 遍历被压缩的消息
// 2. 提取：工具调用 + 结果摘要 + 关键发现
// 3. 生成一段 markdown 摘要
// 4. 返回：[system_prompt, compression_summary_message, ...preservedMessages]
```

压缩不调用 LLM——用规则提取：
- 工具调用保留 id + 参数摘要（去除原始输出）
- flag 检测结果保留
- findings 列表从 `memory/findings.md` 读取
- 最终拼接为一条 `{"role": "system", "content": "...压缩摘要..."}` 消息

**压缩输出示例：**

输入（15 条消息，~50k tokens 的工具调用 + 原始输出）：
```
assistant: "Let me scan the target..."
tool(nmap): "Starting Nmap 7.94... [200 lines of output] ...PORT STATE SERVICE\n22/tcp open ssh\n80/tcp open http"
assistant: "Found SSH and HTTP. Let me check the web server..."
tool(curl): "<html><head><title>Apache Tomcat...</head></html>"
...（10 more steps）
```

输出（1 条摘要消息 + 5 条最近消息，~8k tokens）：
```markdown
## Compression Summary (Steps 1-10 of session abc123)

### Reconnaissance
- Target: 10.0.0.1
- Open ports: 22 (SSH, OpenSSH 8.9), 80 (HTTP, Apache Tomcat 9.0.50)
- Web app: Tomcat Manager found at /manager/html

### Exploitation Attempts
- Tomcat default credentials (tomcat:tomcat) → SUCCESS, gained Manager access
- Deployed WAR reverse shell → SUCCESS, got shell as www-data
- SSH with tomcat credentials → FAILED (no SSH access for tomcat user)

### Key Findings
- Current shell: www-data@target
- Found /etc/shadow hash for user 'admin'
- Sudo binary at /usr/bin/sudo (version 1.9.3p1, potentially CVE-2021-3156)

### Failed Paths
- Tomcat default password tomcat:tomcat → SUCCESS (not failed, but noting)
- Direct root access via SSH → connection refused on port 22 from outside

### Current State
- Phase: lateral (attempting privilege escalation)
- Objective: Escalate from www-data to root
```

#### 3. 重写 Agent Loop (`src/agent-loop.ts`)

**关键架构决策：onStepFinish 混合模式**

Oracle 审查指出：每步单独调用 `streamText` 会导致每次 API 调用重传 system prompt + 历史消息，20 步攻击可能增加 10-30 秒延迟。

**解决方案：保持多步 `streamText`，通过 `onStepFinish` 回调在步间插入 Harness 检查。**

```typescript
// 新的 agent-loop.ts 伪代码

// === 完整接口定义 ===
export interface AgentLoopOptions {
  provider: Provider;             // LLM provider（保留）
  messages: ModelMessage[];       // 初始消息历史（保留）
  tools: ToolDef[];               // 工具列表（保留）
  maxIterations: number;          // 最大迭代次数（保留）
  sessionDir: string;             // 新增：session 目录路径
  harnessConfig: HarnessConfig;   // 新增：Harness 配置
  initialObjective: string;       // 新增：初始攻击目标
  onToken?: (token: string) => void;  // 保留
  onToolCall?: (call: ToolCall) => void;  // 保留
  onFlag?: (flag: string) => void;   // 保留
}

export interface AgentLoopResult {
  messages: ModelMessage[];       // 完整消息历史
  flags: string[];                // 找到的所有 flag
  iterations: number;             // 实际迭代次数
  terminationReason: string;      // 终止原因
}

// === 辅助函数定义 ===

// buildSystemPrompt: 注入当前记忆上下文到 system prompt
// 读取 state.md + memory/ 内容，拼接为完整 system prompt
function buildSystemPrompt(memory: MemoryManager): string {
  const basePrompt = getBaseSystemPrompt(); // FSM 路由提示
  const state = await memory.readState();
  const findings = await memory.readFile("findings");
  const failedPaths = await memory.readFile("failed-paths");
  return `${basePrompt}\n\n## Current Context\n${state}\n\n## Known Findings\n${findings}\n\n## Failed Paths\n${failedPaths}`;
}

// buildTools: 包装工具集，添加权限评估 + 记忆上下文
// 将 state-read/state-write/memory-query/memory-write 加入工具列表
// 保留现有的权限评估逻辑（从 agent-loop.ts 内联代码提取）
function buildTools(baseTools: ToolDef[], memory: MemoryManager): ToolDef[] {
  const memoryTools = [StateReadTool, StateWriteTool, MemoryQueryTool, MemoryWriteTool]
    .map(t => injectSessionDir(t, memory.sessionDir));
  return [...baseTools, ...memoryTools]; // 权限评估在 execute 内部
}

// processStep: 从流式响应中收集结构化结果
// 等待 fullStream 完成，收集 assistant message + tool calls + tool results
// 返回 { newMessages, fullText, toolCalls }
async function processStep(response: StreamTextResult): Promise<StepResult> {
  const fullText: string[] = [];
  const toolCalls: ToolCall[] = [];
  for await (const part of response.fullStream) {
    if (part.type === "text-delta") fullText.push(part.textDelta);
    if (part.type === "tool-call") toolCalls.push(part);
  }
  return {
    newMessages: response.response.messages,
    fullText: fullText.join(""),
    toolCalls,
  };
}

// formatStepLog: 从 StepResult 提取简要日志行
// 格式: "Step 5: nmap -sV 10.0.0.1 → found ports 22,80,443"
function formatStepLog(step: StepResult, iteration: number): string {
  const calls = step.toolCalls.map(c => `${c.toolName}(${JSON.stringify(c.args).slice(0, 80)})`).join(", ");
  return `Step ${iteration}: ${calls || "(thinking)"} → ${step.fullText.slice(0, 100)}`;
}

// === 主循环 ===
export async function runAgentLoop(options: AgentLoopOptions): Promise<AgentLoopResult> {
  const harness = new Harness(options.harnessConfig);
  const memory = new MemoryManager(options.sessionDir);
  const allFlags: string[] = [];
  let shouldTerminate = false;
  let terminationReason = "";

  // 初始化 state.md 和 memory/ 目录
  await memory.ensureDir();
  await memory.initState(options.initialObjective);

  let messages = options.messages;
  let iteration = 0;
  let pendingLoopWarning: string | null = null;

  // 外层循环：每次调用 streamText 执行到 Harness 触发终止或 maxIterations
  while (!shouldTerminate && iteration < options.maxIterations) {

    // === 执行多步 LLM 调用，通过 onStepFinish 在步间检查 ===
    const response = await streamText({
      model: options.provider.languageModel(),
      system: await buildSystemPrompt(memory),
      messages,
      tools: buildTools(options.tools, memory),
      maxSteps: options.maxIterations - iteration, // 剩余步数
      onStepFinish: async ({ response: stepResponse }) => {
        iteration++;

        // --- Harness 观察点 1：循环检测 ---
        const loopResult = harness.checkLoop(stepResponse.messages);
        if (loopResult.isLoop && loopResult.repeatCount >= harness.config.loop.maxRepeats) {
          pendingLoopWarning = loopResult.suggestion;
        }

        // --- Harness 观察点 2：终止判断 ---
        const state = await memory.readState().catch(() => null);
        const termResult = harness.checkTermination(stepResponse.messages, state);
        if (termResult.shouldTerminate) {
          shouldTerminate = true;
          terminationReason = termResult.reason!;
          return; // 停止后续步骤
        }

        // --- Harness 观察点 3：上下文预算 ---
        // token 计数：使用 response.usage.promptTokens（streamText 完成后可用）
        const budgetResult = harness.checkBudget(stepResponse.messages, response.usage?.promptTokens);
        if (budgetResult.shouldCompress) {
          const compressed = await memory.compress(
            messages, harness.config.budget.preserveRecentSteps
          );
          messages = compressed.messages;
          await memory.appendLog(`Compressed: saved ${compressed.tokensSaved} tokens`);
        }
        if (budgetResult.action === 'terminate') {
          shouldTerminate = true;
          terminationReason = 'budget_exhausted';
          return;
        }

        // --- 更新 attack-log ---
        const stepLog = formatStepLog({ newMessages: stepResponse.messages, fullText: "", toolCalls: [] }, iteration);
        await memory.appendLog(stepLog);

        // --- 检测 flag ---
        const fullText = stepResponse.messages.map(m => typeof m.content === 'string' ? m.content : '').join(' ');
        const flags = detectFlags(fullText);
        for (const f of flags) {
          allFlags.push(f);
          options.onFlag?.(f);
        }
      },
    });

    // 处理流式输出（保留流式能力）
    for await (const part of response.fullStream) {
      if (part.type === "text-delta") {
        options.onToken?.(part.textDelta);
      }
    }

    // 收集完整响应
    messages.push(...response.response.messages);

    // 注入循环纠偏提示（如果 onStepFinish 检测到循环）
    if (pendingLoopWarning) {
      messages.push({ role: "system", content: pendingLoopWarning });
      pendingLoopWarning = null;
    }
  }

  if (!terminationReason) terminationReason = `max_iterations_${iteration}`;
  await memory.appendLog(`Terminated: ${terminationReason}`);

  return { messages, flags: allFlags, iterations: iteration, terminationReason };
}
```

关键变化 vs 当前实现：
- 保持多步 `streamText` 调用，通过 `onStepFinish` 回调在步间插入 Harness 检查（避免每步单独 API 调用的延迟）
- Harness 检查点：循环检测、终止判断、上下文预算（在 `onStepFinish` 中执行）
- 新增 MemoryManager 管理状态文件
- 工具集扩展：`state-read`、`state-write`、`memory-query`、`memory-write`
- 返回类型从 `Promise<ModelMessage[]>` 变为 `Promise<AgentLoopResult>`（破坏性变更，需更新所有调用点）

#### 4. System Prompt 重写 (`src/llm/system-prompt.ts`)

新的 system prompt 包含 FSM 路由提示（自然语言，非代码）：

```markdown
You are openhack, an AI agent specializing in security challenges.

## State Management

You have a state file (state.md) that tracks your current objective, phase, and findings.
Update it after every significant action using the state-write tool.

Phases: recon → exploit → lateral → escalate → done
- recon: Gather information, enumerate targets, identify attack surface
- exploit: Attack specific vulnerabilities
- lateral: Move through the network to new targets
- escalate: Escalate privileges
- done: Challenge solved or all approaches exhausted

## Memory

You have persistent memory files:
- attack-log.md: Your actions are logged here automatically
- findings.md: Update this with key discoveries (ports, vulns, credentials)
- failed-paths.md: Record failed approaches to avoid repeating them

Read these files at the start of each session and update them as you work.

## Key Rules

- NEVER read challenge.json for the flag
- ALWAYS update state.md after each significant step
- ALWAYS record failed approaches in failed-paths.md
- If stuck after 3 similar attempts, switch to a completely different approach
- Keep tool outputs small — use grep/head/tail to filter
- When you find the flag, set Phase to "done" in state.md
```

### 错误处理策略

所有文件操作必须容错——不能因为记忆系统故障导致 agent 崩溃：

1. **目录初始化**：`MemoryManager` 构造时调用 `ensureDir()`，创建 `memory/` 目录（`recursive: true`）
2. **state.md 读取失败**：返回空模板 `"## Phase\nrecon\n## Objective\n(unknown)"`，不抛出异常
3. **state.md 写入失败**：catch 错误，emit `HackEvent.STATE_UPDATED` 带 error 标记，继续循环
4. **memory/ 文件不存在**：`memory-query` 返回 `"(empty)"`，`compressor` 跳过缺失文件
5. **压缩产生异常结果**：如果压缩后消息长度反而增加，跳过压缩，记录 warning 到 attack-log
6. **Phase 解析失败**：`parsePhaseFromState` 返回 null → Terminator 跳过 agent-declared-done 检查

### Token 计数策略

`BudgetGuard` 需要估算当前上下文 token 用量。策略：

- **首选**：使用 `response.usage.promptTokens`（Vercel AI SDK 在 streamText 响应完成后提供）
- **备选**：字符估算 `Math.ceil(text.length / 4)`（约 4 字符 = 1 token）
- **实现**：`checkBudget(messages, usageTokens?: number)` — 有精确值用精确值，否则估算

## Open Questions

1. **state.md 的并发安全**：如果后续扩展到多 agent 并行，state.md 需要加锁。当前单 agent 架构不需要，但设计上要预留接口。
2. **压缩策略是否需要 LLM 参与**：当前设计用规则提取（不调用 LLM），但更高质量的摘要可能需要一次 LLM 调用。这是成本/质量的权衡。
3. **loop detection 的哈希算法**：工具参数的相似度比较用 Jaccard（词袋）还是编辑距离？对渗透场景来说，参数往往是命令字符串，Jaccard 可能更合适。
